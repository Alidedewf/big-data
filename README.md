## 1. Apache HBase

Apache HBase — распределённая, масштабируемая, колонно-ориентированная база данных, работающая поверх HDFS. Она рассчитана на большие объёмы структурированных, полуструктурированных и разреженных данных, когда важен быстрый доступ к строкам по ключу.

Основные компоненты:

| Компонент | Назначение |
| --- | --- |
| HMaster | Управляет кластером и распределением регионов |
| RegionServer | Хранит регионы таблиц и обслуживает запросы |
| ZooKeeper | Координирует работу компонентов и поддерживает отказоустойчивость |
| HFile | Формат физического хранения данных в HDFS |

Строка идентифицируется `row key`. Колонки объединяются в семейства колонок (`column family`), которые физически хранятся вместе. Каждое значение может иметь несколько версий, различаемых временной меткой.

## 2. Структура таблицы

Создана таблица `students` с семействами колонок `info` и `grades`:

```text
students
└── row key: 1001
    ├── info:name = Aigerim
    ├── info:age = 22
    └── grades:math = 95
```

`1001` — уникальный ключ строки. `info:name` означает колонку `name` внутри семейства `info`; `grades:math` — колонку `math` внутри семейства `grades`.

## 3. HBase Shell: создание таблицы и CRUD

Полный набор команд находится в [hbase_shell_commands.txt](practice-07/hbase_shell_commands.txt).

### Создание таблицы

```ruby
create 'students', 'info', 'grades'
```

### Добавление данных

```ruby
put 'students', '1001', 'info:name', 'Aigerim'
put 'students', '1001', 'info:age', '22'
put 'students', '1001', 'grades:math', '95'
```

### Чтение данных

```ruby
get 'students', '1001'
scan 'students'
```

### Обновление и удаление

```ruby
put 'students', '1001', 'grades:math', '98'
delete 'students', '1001', 'info:age'
```

Команда `put` обновляет значение по тому же row key и колонке. После обновления оценка по математике равна 98. `delete` удаляет конкретную ячейку, после чего `info:age` отсутствует. Таблицу HBase удаляют в два шага:

```ruby
disable 'students'
drop 'students'
```

## 5. Python API через HappyBase

HappyBase — Python-клиент для HBase Thrift API. Скрипт [hbase_api.py](practice-07/hbase_api.py) подключается к Thrift Server на `localhost`, создаёт таблицу при отсутствии, добавляет строку, читает её, обновляет оценку, удаляет возраст и сканирует таблицу.

```python
connection = happybase.Connection("localhost")
connection.open()

table = connection.table("students")
table.put(b"1001", {b"grades:math": b"98"})
table.delete(b"1001", columns=[b"info:age"])

for row_key, data in table.scan():
    print(row_key, data)
```

Для запуска нужен HBase и Thrift Server. Команды:

```bash
start-hbase.sh
hbase-daemon.sh start thrift
source .venv/bin/activate
python -m pip install -r requirements.txt
python practice-07/hbase_api.py
```

Автоматический запуск Shell-команд подготовлен в [run_hbase.sh](practice-07/run_hbase.sh).

## 7. Отличие HBase от SQL-БД

HBase не является реляционной СУБД. В ней нет привычных SQL-join, внешних ключей, фиксированной схемы всех колонок и транзакций между несколькими строками в стиле SQL-БД. HBase оптимизирован для доступа по row key, записи большого потока данных, горизонтального масштабирования и разреженных таблиц с большим числом потенциальных колонок.

Преимущества HBase:

- масштабирование на кластер Hadoop;
- быстрые чтение и запись строк по ключу;
- гибкая модель колонок и хранение версий значений;
- интеграция с HDFS, MapReduce и другими инструментами Hadoop.

Недостатки:

- сложнее установить и администрировать, чем обычную SQL-БД;
- не подходит для сложной аналитики с соединениями и произвольным поиском без ключа;
- неверно выбранный row key может создать горячие регионы и снизить производительность.

## 8. Ответы на контрольные вопросы

### 1. Чем HBase отличается от HDFS и Hadoop MapReduce?

HDFS — распределённая файловая система, которая хранит файлы блоками. MapReduce — модель пакетных вычислений над данными. HBase — база данных поверх HDFS, предоставляющая быстрый доступ к отдельным строкам и колонкам по ключу. HBase может использовать инфраструктуру Hadoop, но решает задачу оперативного доступа к данным, а не только хранения файлов или пакетной обработки.

### 2. Что такое Column Family и почему она важна?

Column Family — группа логически связанных колонок, например `info` или `grades`. Семейства задаются при создании таблицы и влияют на физическое хранение, настройку сжатия, версий и производительность. Поэтому их нужно проектировать заранее по типичным сценариям чтения и записи.

### 3. Как обеспечивается отказоустойчивость в HBase?

Данные HBase хранятся в HDFS, который реплицирует блоки на нескольких узлах. ZooKeeper координирует состояние кластера, а HMaster перераспределяет регионы при отказах RegionServer. Журнал WAL помогает восстановить ещё не записанные на диск изменения.

### 4. Какие существуют аналоги HBase?

Близкие по назначению системы: Google Bigtable, Apache Cassandra, ScyllaDB, Amazon DynamoDB и Google Cloud Bigtable. Они отличаются моделью согласованности, способом масштабирования и экосистемой.

### 5. В каких задачах HBase предпочтительнее традиционных СУБД?

HBase подходит для больших разреженных таблиц, временных рядов, логов, телеметрии IoT, профилей пользователей и систем, где нужны масштабируемые записи и чтение по ключу. Для транзакционных бизнес-приложений со сложными связями, ограничениями и SQL-запросами чаще подходят реляционные СУБД.
